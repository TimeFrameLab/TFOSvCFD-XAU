# TimeFrame Operation System — CFD Gold

*A disciplined gold CFD market analysis system powered by systematic workflows and MPTM Architecture.*

## 📋 ภาพรวม

**TimeFrame Operation System — CFD Gold** คือระบบวิเคราะห์ตลาด CFD ทองคำอย่างมีวินัย โดยใช้ workflow ที่ทำซ้ำและตรวจสอบย้อนกลับได้ พร้อมสถาปัตยกรรม **MPTM (Multi-Timeframe)** เพื่อจัดระเบียบการวิเคราะห์ตามกรอบเวลา

ระบบมุ่งช่วยจัดข้อมูลและเงื่อนไขตลาดให้เป็นขั้นตอน ไม่ใช่ระบบส่งคำสั่งซื้อขาย และไม่ใช่คำแนะนำการลงทุน

> **สถานะ: อยู่ระหว่างพัฒนา — ห้ามใช้ผลวิเคราะห์เพื่อตัดสินใจลงทุนจริง**
>
> workflow และเกณฑ์เฉพาะสำหรับ CFD Gold ยังต้องกำหนดและตรวจสอบให้ครบก่อนใช้งานจริง สคริปต์ที่อยู่ใน repository ปัจจุบันยังไม่ได้รับการยืนยันว่าเป็นเครื่องมือวิเคราะห์ XAU CFD

## ✅ ข้อกำหนดบังคับเรื่องการแสดงผล (Output Contract)

ก่อนแสดงผลทุกครั้ง ต้องยึดหลักต่อไปนี้:

- ใช้ข้อมูลที่ระบุแหล่งที่มาและเวลาของข้อมูลได้
- ระบุ timeframe ที่ใช้จริง และไม่อนุมานว่ามีข้อมูลในกรอบเวลาที่แหล่งข้อมูลไม่ได้ให้มา
- แยกข้อมูลตลาด ข้อสังเกต และเงื่อนไขของแบบจำลองออกจากกัน
- `UPDATE` ใช้รูปแบบรายงานภาพรวม ส่วน `UPDATE/<SYMBOL>` ใช้รายงานรายสัญลักษณ์ และ `CANDIDATE` ใช้เกณฑ์คัดกรองที่ประกาศไว้เท่านั้น
- เมื่อข้อมูลหรือ workflow ไม่พร้อม ให้รายงานข้อจำกัดหรือข้อผิดพลาดตามจริง ไม่แสดงรายงานสำเร็จแทน
- ไม่ใช้ข้อมูลเก่าแทนข้อมูลล่าสุดโดยไม่เปิดเผย และไม่คาดเดาค่าที่ขาด
- ผลวิเคราะห์เป็นข้อมูลประกอบการพิจารณา ไม่ใช่คำสั่งซื้อขายหรือคำแนะนำการลงทุน

workflow เป้าหมายของระบบแบ่งเป็นการสรุปภาพรวมตลาด (`UPDATE`), วิเคราะห์รายสัญลักษณ์ (`UPDATE/<SYMBOL>`) และคัดกรอง setup (`CANDIDATE`) โดยต้องใช้กติกา MPTM รุ่น CFD Gold ที่ระบุและตรวจสอบได้

ยังไม่มีการกำหนดเกณฑ์ตัวเลขสำหรับแนวโน้ม โมเมนตัม การยืนยัน setup หรือการจัดประเภทสถานะใน README นี้ จึงห้ามนำเกณฑ์จากสินทรัพย์หรือระบบอื่นมาใช้แทนโดยอัตโนมัติ

### 🔍 สถาปัตยกรรม MPTM

- **Multi-Timeframe Context**: พิจารณาความสัมพันธ์ของกรอบเวลาตามที่ workflow กำหนด
- **Systematic Workflow**: ดำเนินการตามลำดับที่ทำซ้ำและตรวจสอบย้อนหลังได้
- **Signal Confirmation**: ระบุสัญญาณและเงื่อนไขยืนยันจากข้อมูลต้นทาง
- **Structure and Levels**: แสดงระดับราคาและบริบทพร้อมที่มา
- **Risk and Invalidation**: ระบุความเสี่ยงและเงื่อนไขที่ทำให้ setup ใช้ไม่ได้
- **Data Integrity**: ตรวจสอบความครบถ้วน เวลา และความเหมาะสมของข้อมูลก่อนวิเคราะห์

องค์ประกอบเหล่านี้อธิบายหลักการออกแบบ ไม่ใช่การรับรองว่าแต่ละส่วนถูกนำไปใช้ในโค้ดแล้ว

### 📊 รายงานและบันทึกการวิเคราะห์

รายงานควรบันทึกสินทรัพย์ แหล่งข้อมูล timestamp เขตเวลา timeframe รุ่นของ workflow และผลวิเคราะห์ เพื่อให้ตรวจสอบย้อนหลังได้ รูปแบบไฟล์และตำแหน่งจัดเก็บจะระบุเมื่อ workflow ของ CFD Gold พร้อมใช้งาน

### 🎯 การจำแนกสถานะ

สถานะของตลาดหรือ setup ต้องใช้คำจำกัดความและเกณฑ์จาก workflow CFD Gold ที่ผ่านการตรวจสอบเท่านั้น หากเกณฑ์ยังไม่กำหนด ให้รายงานเป็นข้อสังเกตโดยไม่ติดป้ายสถานะซื้อขาย

สถานะใด ๆ ไม่ใช่คำสั่งซื้อขายหรือการรับประกันผลลัพธ์ และไม่ควรใช้แทนการจัดการความเสี่ยง

## 📈 แหล่งข้อมูลตลาด

แหล่งข้อมูล CFD Gold และวิธีตรวจสอบความสดของข้อมูลยังต้องกำหนดสำหรับ workflow รุ่นนี้ ทุกผลวิเคราะห์ต้องระบุผู้ให้บริการหรือแหล่งข้อมูล timestamp เขตเวลา และข้อจำกัดที่เกี่ยวข้อง เช่น ความแตกต่างของราคา CFD ระหว่างผู้ให้บริการ

หากข้อมูลราคาไม่พร้อม ล่าช้า หรือไม่สามารถยืนยันแหล่งที่มาได้ ให้หยุดการวิเคราะห์ส่วนที่ได้รับผลกระทบและแจ้งสถานะตามจริง

## 🛡️ ขอบเขตและข้อควรระวัง

- CFD เป็นผลิตภัณฑ์ที่มีความเสี่ยงสูง การใช้ leverage อาจทำให้ขาดทุนอย่างรวดเร็วและมากกว่าเงินที่คาดไว้ ทั้งนี้ขึ้นอยู่กับเงื่อนไขของผู้ให้บริการ
- สัญญาณและรูปแบบ MPTM ไม่รับประกันความถูกต้องหรือผลตอบแทนในอนาคต
- ความคลาดเคลื่อนของราคา spread, slippage, swap, เวลาตลาด และเงื่อนไขของโบรกเกอร์อาจส่งผลต่อผลลัพธ์
- ระบบนี้ไม่ส่งคำสั่งซื้อขาย ไม่จัดการบัญชีโบรกเกอร์ และไม่รับรองความเหมาะสมของธุรกรรมสำหรับผู้ใช้
- ห้ามเผยแพร่ credentials, API keys หรือข้อมูลบัญชีที่เป็นความลับ

## 🛠️ สรุปปัญหาและแนวทางแก้ไข

ขณะ workflow สำหรับ CFD Gold ยังไม่พร้อม อย่าใช้ `update.sh` หรือ `candidate.sh` เป็นเครื่องมือวิเคราะห์ XAU CFD เพราะยังไม่ได้ยืนยันว่าเชื่อมต่อกับ workflow และเกณฑ์ของโปรเจกต์นี้

เมื่อมีการติดตั้ง workflow แล้ว หากวิเคราะห์ไม่ได้ ให้ตรวจสอบตามลำดับ:

1. ตรวจสอบว่าแหล่งข้อมูลและ credentials ที่จำเป็นถูกตั้งค่าอย่างปลอดภัย
2. ตรวจสอบการเชื่อมต่อและสิทธิ์เข้าถึงแหล่งข้อมูล
3. ตรวจสอบ timestamp, timezone, symbol และ timeframe ของข้อมูล
4. ตรวจสอบว่าข้อมูลมีรูปแบบและคอลัมน์ครบตาม workflow รุ่นที่ใช้งาน
5. เมื่อยังยืนยันข้อมูลไม่ได้ ให้รายงานข้อผิดพลาดและหยุด แทนการใช้ข้อมูลเก่าหรือคาดเดาผล
